# StockBoard v2 실시간 파이프라인

최종 갱신: 2026-07-16

이 문서는 StockBoard v2의 실시간 구조와 운영 규칙을 기록하는 단일 기준 문서이다. 기존 StockBoard v0.3.x 문서와 섞지 않는다.

## 1. 현재 구조

```text
32-bit Kiwoom QAx price-only collector
  FID 10 / 12 / 20 / sampled 14
        ↓
64-bit canonical worker
        ├─ ka10004 통합 잔량비 저속 조회
        ├─ WebSocket 0B/FID228 Top20 체결강도
        ├─ ka10046 5분강도 저속 조회
        ├─ ka90004 프로그램 순매수
        ├─ ka10055 대량체결 저속 조회
        └─ 6지표 거래일 수명주기·최종 출력 가드
        ↓
SSE /api/v2/stream
        ↓
StockBoard 표시 전용 HTML
```

생산 가격 collector 계약:

```text
_REALTIME_FIDS = 10;12;20;14
single QAx owner
large_trade_enabled = False
```

두 번째 QAx 로그인·실시간 등록과 FID15의 생산 재도입은 금지한다.

## 2. 6지표 원천

| 지표 | 장중 원천 | 장마감·08:00 전 |
|---|---|---|
| 대금비 | 당일 누적 거래대금 ÷ 전일 거래대금 | 같은 거래일 최종값 |
| 잔량비 | `ka10004`, 통합 코드 `_AL` | 직전 거래일 최종 정상값 |
| 체결강도 | WebSocket 주식체결 `0B/FID228`, Top20 | 마지막 정상 FID228 |
| 5분강도 | `ka10046`의 5분 필드만 | 직전 거래일 최종 정상값 |
| 프로(억) | `ka90004` | 직전 거래일 최종값 |
| 대량체결 | `ka10055` 저속 최근 페이지, 5천만원 기준 | 직전 거래일 최종 누적값 |

`ka10046`의 일반 체결강도 필드는 화면의 체결강도로 사용하지 않는다. 열 제목은 키움 원래 명칭인 `체결강도`를 사용한다.

## 3. 공통 거래일 수명주기

```text
정규장·애프터마켓   현재 거래일 값만 허용
20:00 이후~08:00 전 직전 완료 거래일 최종값만 허용
08:00 프리마켓      전일 보존값 만료
날짜 불명·과거 오염 표시 금지
null·빈문자         0이 아니라 '-'
```

통합 snapshot:

```text
data/runtime/stockboard_v2/six_metric_lifecycle.json
```

실제 값이 변할 때만 최대 5초에 한 번 저장한다. 최종 출력 가드는 거래일과 원천이 일치하지 않는 잔여값을 제거한다.

## 4. 시장시간별 수집

| 구간 | 정책 |
|---|---|
| 00:00~08:00 | 직전 거래일 값이 빠진 경우 잔량비·5분강도만 통합 `_AL`로 저빈도 보충 |
| 08:00~09:00 | 전일 hold 만료, 당일 실시간 준비 |
| 09:00~09:10 | 가격 fast patch 유지, 보조 TR 최소화, 전체 테이블 heavy render 1초 제한 |
| 09:10~15:30 | 현재 거래일 데이터 수집 |
| 15:30~20:00 | 통합 `_AL` 잔량비·5분강도, NXT 미거래 종목은 같은 거래일 마지막 정상값 유지 |
| 20:00 이후 | 신규 장중 수집 중지, 직전 거래일 최종값 유지 |

잔량비와 5분강도의 08:00 전 보충 간격:

```text
S1       900초
Top20  21600초
대량체결 보충 없음
```

## 5. 체결강도

- 공식 실시간 원천은 WebSocket 주식체결 `0B/FID228`이다.
- 한 WebSocket 연결에서 Top20을 구독한다.
- 종목별 최신값을 1초 동안 모아 한 번의 state lock과 한 번의 background rebuild로 반영한다.
- 20초 이상 새 체결이 없으면 장중 현재값으로 표시하지 않는다.
- 장중 수집된 최종값은 장마감 후 다음 프리마켓 직전까지 유지한다.

## 6. 5분강도

- `ka10046`의 5분·20분·60분 필드만 저장한다.
- 같은 응답의 일반 체결강도 필드는 폐기한다.
- 다른 REST 지표와 단일 요청 예산을 공유한다.
- 0·빈값·오류는 마지막 정상값을 덮어쓰지 않는다.

## 7. 대금비와 NXT 미거래

```text
amount_ratio = trade_value_eok / prev_trade_value_eok
```

NXT 거래가 없는 종목도 정규장 최종 누적 거래대금이 있으면 애프터마켓과 장마감에 대금비를 유지한다. 거래일이 다른 값은 사용하지 않는다.

## 8. 프로그램

프로그램 조회시각과 값의 대상 거래일을 분리한다. 00:00~08:00에 조회한 직전 거래일 최종값은 조회일이 아니라 `last_completed_trading_date`로 태깅한다. 프리마켓부터는 당일 데이터가 들어올 때까지 전일값을 현재값처럼 사용하지 않는다.

## 9. 대량체결

가격 collector에 FID15를 추가하지 않는다. `ka10055` 최근 첫 페이지만 저속 조회한다.

```text
정규장 S1          60초
정규장 Top20       300초
애프터 S1          120초
애프터 Top20       600초
09:00~09:10 S1     180초
09:00~09:10 Top20  중지
```

첫 조회 시 당일 저장값이 없으면 페이지 집계로 초기화한다. 당일 저장값이 있으면 첫 페이지는 중복방지 기준선으로 사용하고 이후 새 signed 체결만 증분 반영한다.

표시 상태 `partial_recent_page_since_activation`은 전 종일 완전 집계가 아니라 저부하 최근 페이지 기준임을 뜻한다.

## 10. AHK HTS 연동

`Edit6`가 여러 개이면 모두 거부하지 않는다. 다음 조건을 점수화해 유일한 최고점 컨트롤만 사용한다.

```text
nkre.exe
_NKHeroMainClass / NHeroMainClass
영웅문 제목
가시·활성 상태
최소화 여부
창 크기
```

동점이면 안전하게 전송하지 않는다. HTS를 활성화하거나 포커스를 빼앗지 않고 검증된 Edit HWND에만 코드와 Enter를 보낸다.

## 12. 검증 원칙

- 프리마켓·정규장·애프터마켓 실제 HTS 대조 전에는 Draft PR을 유지한다.
- queue·drop·stream latency·render·collector PID 생존을 함께 확인한다.
- 잘못된 값을 억지로 채우는 것보다 `-`로 차단하는 것을 우선한다.
- 장중 수집에 성공한 값은 장마감·재시작 후 다음 프리마켓 직전까지 유지되어야 한다.
