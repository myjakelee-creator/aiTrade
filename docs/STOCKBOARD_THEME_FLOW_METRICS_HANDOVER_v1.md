# StockBoard 국내주식 테마 흐름 지표 적용 인계서 v1

작성 기준: 2026-07-15  
대상 저장소: `myjakelee-creator/aiTrade`  
대상 시스템: `StockBoard`  
목적: OKXTrade에서 검증 중인 테마 흐름 지표를 국내주식 실시간 전광판에 안전하게 이식하기 위한 설계·구현 기준

---

## 1. 핵심 목적

국내주식에서도 종목 단위 등락률·거래대금만 보는 것을 넘어 다음 흐름을 테마 단위로 빠르게 판단한다.

**자금 유입 → 매수 우위 → 거래대금 가속 → 테마 확산 → 대장주 집중 여부**

최종 화면은 다음 질문에 답해야 한다.

| 판단 질문 | 핵심 지표 |
|---|---|
| 지금 실제 매수 자금이 들어오는가 | 공격매수 |
| 매수와 매도 중 어느 쪽이 우세한가 | 매수우위 |
| 직전 구간보다 거래가 빨라지고 있는가 | 가속·대금가속 |
| 한 종목만 오르는가, 테마 전체가 오르는가 | 상승 참여 |
| 테마 자금이 대장주 한 종목에 얼마나 몰렸는가 | 집중도 |

이 기능은 기존 후보5·등급·모멘텀을 즉시 대체하지 않는다. 먼저 독립적인 **테마 흐름 관찰 모듈**로 연결하고 실전·리플레이 검증 후 점수모델 입력값으로 사용할지를 결정한다.

---

## 2. 기존 StockBoard 구조에서의 위치

기존 원칙을 유지한다.

```text
OpenAPI 실시간 체결·호가
→ RealtimeStore
→ Theme Flow Engine
→ StockBoard Server API
→ HTML 표시
```

역할 분리는 다음과 같다.

| 계층 | 책임 |
|---|---|
| `kiwoom_data_provider.py` | 원본 체결·호가 필드 수신, 종목코드·시각 정규화 |
| `stockboard_store.py` | 종목별 최신 상태와 초 단위·분 단위 event bucket 보존 |
| `stockboard_engine.py` | 현재/직전 구간 계산, 테마 집계, 상태 판정 |
| `stockboard_server.py` | 계산 결과를 읽기 전용 API로 전달 |
| `docs/stockboard_v0_3_0_sample.html` | 서버 결과 표시만 담당 |

### 불가침 원칙

- HTML에서 공격매수·가속·집중도를 계산하지 않는다.
- 현재가·등락률 원천을 이 기능 때문에 변경하지 않는다.
- `_AL`·KRX·NXT 원천 정책을 임의 수정하지 않는다.
- 기존 후보5·등급·모멘텀 점수를 바로 교체하지 않는다.
- 주문·자동매매·예약 실행·클라우드 업로드를 추가하지 않는다.

## 3. 국내주식 시간 버튼 정의

OKXTrade와 같은 비교 구조를 사용한다.

| 버튼 | 현재 구간 | 비교 구간 | 국내주식 용도 |
|---|---:|---:|---|
| 실시간 | 최근 10초 | 직전 10초 | 장초반 순간 자금 유입·급가속 탐지 |
| 1분 | 최근 60초 | 직전 60초 | 짧은 체결 흐름과 초기 지속성 확인 |
| 5분 | 최근 5분 | 직전 5분 | 주도 테마 지속·확산 확인 |
| 15분 | 최근 15분 | 직전 15분 | 일시 급등과 추세형 상승 구분 |

예: 현재 시각 10:20, 5분 선택

```text
현재 구간: 10:15:00~10:20:00
직전 구간: 10:10:00~10:15:00
```

### 데이터 준비 상태

- 10초: 라이브 체결 20초가 쌓이기 전 `축적중`
- 1분: 라이브 체결 2분이 쌓이기 전 `축적중`
- 5분·15분: 저장된 틱 또는 신뢰 가능한 분 단위 공격매수/매도 history가 있을 때 즉시 계산
- 공격 방향 history가 없고 일반 1분봉만 있으면 전체 거래대금만 보강하고, 공격매수·매수우위는 임의 복원하지 않는다.

## 4. 국내주식 지표 정의

## 4.1 공격매수

선택 구간에서 매수자가 호가를 적극적으로 체결한 거래대금 합계다.

```text
공격매수 = Σ(공격매수 판정 체결가격 × 체결수량)
```

### 체결 방향 판정 우선순위

국내 OpenAPI는 Binance `taker side`와 동일한 단일 필드가 보장되지 않으므로 다음 우선순위를 사용한다.

| 우선순위 | 판정 방법 | 원칙 |
|---:|---|---|
| 1 | OpenAPI 원본 필드가 매수·매도 체결 방향을 직접 제공하고 HTS와 검증된 경우 | 최우선 사용 |
| 2 | 체결가가 직전 최우선 매도호가 이상이면 공격매수, 최우선 매수호가 이하이면 공격매도 | 호가 동기화가 정상일 때 사용 |
| 3 | 직전 체결가 대비 상승 체결은 매수, 하락 체결은 매도로 분류 | 보조 fallback |
| 4 | 위 조건으로 판정할 수 없는 체결 | `unknown`으로 보존 |

### 중요한 원칙

- 체결강도는 공격매수대금과 같은 값이 아니다.
- 체결강도를 이용해 공격매수 금액을 역산하지 않는다.
- 판정 불가능한 체결을 임의로 50:50 분배하지 않는다.
- 원본 FID 의미와 부호는 `OPENAPI_HELP_MASTER_UPDATED_20260625.md` 및 HTS 실측으로 먼저 검증한다.

---

## 4.2 공격매도

```text
공격매도 = Σ(공격매도 판정 체결가격 × 체결수량)
```

공격매수와 공격매도는 같은 판정 체계에서 생성해야 한다. `unknown`은 별도로 보존한다.

---

## 4.3 전체 최근 체결대금

```text
전체 체결대금 = 공격매수 + 공격매도 + unknown
```

가속과 집중도는 시장 활동 전체를 보기 위해 `unknown`까지 포함한 전체 체결대금을 기본값으로 사용한다.

매수우위는 방향이 확정된 체결만 사용한다.

---

## 4.4 매수우위

```text
매수우위 = 공격매수 ÷ (공격매수 + 공격매도) × 100
```

| 값 | 해석 |
|---:|---|
| 40% 이하 | 공격매도 우세 |
| 50% | 매수·매도 균형 |
| 55% 이상 | 매수 약우세 |
| 60% 이상 | 강한 공격매수 우세 |
| 70% 이상 | 매수 한쪽으로 과도하게 집중될 가능성 |

방향 확정 체결대금이 너무 적으면 `-` 또는 `판정 부족`으로 표시한다.

권장 최소 조건:

```text
방향 확정 체결대금 ÷ 전체 체결대금 ≥ 70%
```

이 조건 미달 시 숫자는 계산하더라도 `low_confidence=true`를 함께 전달한다.

---

## 4.5 가속

현재 구간의 전체 체결대금이 직전 동일 구간보다 얼마나 증가했는지 나타낸다.

```text
가속 = 현재 구간 전체 체결대금 ÷ 직전 구간 전체 체결대금 × 100
```

| 값 | 의미 |
|---:|---|
| 50% | 직전 구간의 절반 수준 |
| 100% | 직전 구간과 동일 |
| 150% | 직전보다 1.5배 증가 |
| 200% | 직전보다 2배 증가 |
| 300% 이상 | 거래대금 급증 |

직전 구간이 0인 경우 임의의 무한대 값을 만들지 않는다.

권장 표시:

- 현재도 0 → `0%`
- 현재 > 0, 직전 = 0 → `신규 유입`
- 데이터 부족 → `축적중`

---

## 4.6 대금가속

대금가속은 가속과 같은 계산값을 막대로 표현한다.

```text
가속 숫자 = 정확한 비율 표시
대금가속 막대 = 같은 비율을 시각적으로 표시
```

권장 막대 기준:

```text
100% → 막대 약 1/3
200% → 막대 약 2/3
300% 이상 → 막대 가득
```

가속과 대금가속을 서로 다른 지표처럼 별도 계산하지 않는다.

---

## 4.7 상승 참여

테마 전체 구성 종목 중 전일 종가 대비 현재가가 상승한 종목 수다.

```text
상승 참여 = 상승 종목 수 / 유효 가격 종목 수
```

예:

```text
반도체 12종목 중 9종목 상승 → 9/12
```

### 국내주식 기준

- 등락 기준: 전일 정규장 종가 대비 현재 정규장 표시가격
- 가격 원천: 기존 StockBoard 서버 산출 `price/change_rate`
- 장전 예상체결가는 정규장 상승 참여와 혼합하지 않는다.
- 가격 미수신 종목은 분모에서 제외하거나 `invalid_count`로 별도 표시한다.

상승 참여는 선택한 10초·1분·5분 수익률이 아니라 당일 등락 기준이다. 추후 필요하면 `최근 1분 상승 참여`를 별도 지표로 추가하되 기존 의미를 바꾸지 않는다.

---

## 4.8 집중도

선택 구간 테마 전체 체결대금 중 가장 큰 한 종목의 비중이다.

```text
집중도 = 테마 1위 종목 전체 체결대금 ÷ 테마 전체 체결대금 × 100
```

| 값 | 해석 |
|---:|---|
| 20~30% | 여러 종목으로 분산 |
| 40~50% | 대장주가 있으면서 후속주도 참여 |
| 60~70% | 한 종목 중심의 강한 집중 |
| 80% 이상 | 거의 한 종목만 움직이는 독주 가능성 |

집중도는 상승 참여와 함께 해석한다.

| 조합 | 해석 |
|---|---|
| 집중도 높음 + 상승 참여 높음 | 강한 대장주가 테마 전체를 이끄는 상태 |
| 집중도 높음 + 상승 참여 낮음 | 한 종목 독주·후속주 부재 |
| 집중도 낮음 + 상승 참여 높음 | 여러 종목으로 자금이 넓게 확산 |

## 5. 권장 테마 상태 판정 v0.1

초기값은 OKXTrade와 같은 구조로 시작하되 국내주식 실전·리플레이 후 반드시 재보정한다.

| 상태 | 초기 판정 조건 |
|---|---|
| 점화 | 가속 ≥ 180% + 매수우위 ≥ 60% + 상승 참여 ≥ 60% |
| 확산 | 매수우위 ≥ 56% + 상승 참여 ≥ 60% |
| 둔화 | 가속 < 80% 또는 매수우위 < 48% |
| 관찰 | 위 조건에 해당하지 않음 |
| 축적중 | 현재·직전 구간 데이터 부족 |
| 판정 부족 | 방향 확정 체결 비율이 기준 미달 |

이 임계값을 곧바로 매수 신호로 사용하지 않는다.

## 7. 국내시장 고유 예외 처리

## 7.1 정규장과 다른 세션을 혼합하지 않는다

| 구간 | 처리 원칙 |
|---|---|
| 장전 동시호가 | 예상체결 흐름은 별도 상태로 분리 |
| 09:00 정규장 시작 | live bucket 새로 시작 |
| 장중 VI | VI 진입·해제 상태를 표시하고 체결 공백을 가속 급락으로 오판하지 않음 |
| 15:20~15:30 동시호가 | 정규 연속매매 구간과 별도 표시 권장 |
| 15:30 정규장 마감 | regular close snapshot 기준 고정 |
| 시간외/NXT | 정규장 테마 흐름과 혼합하지 않음 |

## 7.2 KRX/NXT/통합 원천

- 운영 종목 key는 6자리로 유지한다.
- 원천 진단용 suffix는 별도 필드에 보존한다.
- 같은 체결을 KRX·NXT·통합에서 중복 집계하지 않는다.
- suffix Store 오염 방지 WIP가 검증되기 전 해당 경로를 이 기능 때문에 수정하지 않는다.

## 7.3 상한가·하한가

- 상한가에서 매도호가가 없거나 하한가에서 매수호가가 없으면 호가 기반 체결 방향 판정이 불가능할 수 있다.
- 가격제한 상태에서는 `price_limit_state`를 함께 전달한다.
- 호가 부재 체결은 임의 방향으로 분류하지 않고 원본 필드 또는 tick rule fallback을 사용한다.

## 7.4 거래정지·신규상장·저유동 종목

- 거래정지 종목은 상승 참여 분모에서 제외한다.
- 신규상장·기준가 예외 종목은 등락률 기준 신뢰도를 별도 표시한다.
- 직전 구간 거래대금이 지나치게 작은 종목은 가속이 과대 표시될 수 있으므로 최소 거래대금 조건을 둔다.

---

## 8. 테마 마스터 원칙

테마는 종목별 단일 분류가 아니라 복수 태그를 허용한다.

```text
삼성전자 → 반도체, HBM, 대형주
SK하이닉스 → 반도체, HBM, 메모리
한미반도체 → 반도체 장비, HBM
```

### 운영 규칙

- 한 종목이 여러 테마에 포함될 수 있다.
- 테마별 계산에는 해당 테마 전체 구성 종목을 사용한다.
- 카드 표시 종목 수와 계산 종목 수를 분리한다.
- 미분류 신규 종목을 버리지 않고 `미분류 국내주식`으로 임시 노출한다.
- ETF·ETN·우선주·스팩·리츠 포함 여부는 기존 `tradable_stock_master.csv` 정책을 우선한다.

| 가속 | 숫자 `%` 또는 `신규 유입/축적중` |
| 상승 참여 | `상승 종목 수/유효 종목 수` |
| 매수우위 | `%` + 신뢰도 경고 가능 |
| 대금가속 | 가속값 막대 |
| 집중도 | 1위 종목 비중 막대 |

### 툴팁 권장 내용

```text
현재 구간 공격매수/공격매도/unknown
직전 구간 전체 체결대금
방향 확정 비율
1위 종목과 비중
현재/직전 시간 범위
```

### 상태 색상 초기안

| 상태 | 색상 |
|---|---|
| 점화 | 빨강 |
| 확산 | 주황 |
| 둔화 | 황갈색 |
| 관찰 | 회색 |
| 축적중 | 회색 점선 또는 별도 라벨 |
| 판정 부족 | 보라 또는 경고 아이콘 |

색상은 등락률 색상과 혼동되지 않도록 카드 좌측 상태선 또는 상태 배지에만 사용한다.

## 11. 구현 순서

## 단계 1. 원본 체결 방향 진단

코드는 계산보다 진단을 먼저 한다.

- 대표 종목 5~10개의 원본 체결 필드 로그
- 체결가·체결량·체결시각·최우선 매수/매도호가·체결강도·원천코드 기록
- HTS 체결창과 매수/매도 방향 대조
- 정규장·VI·상한가·NXT 구간 별도 검증

완료 조건:

```text
공격매수/공격매도 판정 규칙이 HTS 관찰과 일관됨
unknown 비율과 오분류 사례가 문서화됨
```

## 단계 2. 종목별 bucket 구축

- `RealtimeStore`에 초 단위 buy/sell/unknown bucket 추가
- 현재 31분 이상 보존
- 동일 체결 중복 제거
- 6자리 운영 key와 source 진단 필드 분리

## 단계 3. Theme Flow Engine

- 현재/직전 구간 집계
- 종목별 지표 계산
- 테마 전체 합산
- 상태 판정
- 신뢰도·축적중 처리

## 단계 4. 읽기 전용 API

- `/api/theme_flow`
- `/api/theme_flow/status`
- 계산 responsibility는 Python 유지

## 단계 5. UI 연결

- 우선 별도 테마 패널 또는 실험 탭으로 연결
- 기존 후보5·Top100 레이아웃과 계산을 훼손하지 않음
- 숫자 부분 갱신과 구조 갱신 분리

## 단계 6. 리플레이·실전 보정

- 장초반 09:00~09:30 우선 검증
- 점화·확산·둔화 임계값 조정
- 대장주 독주와 테마 확산 구분 검증
- 후보5 점수 입력 여부는 별도 승인

## 12. 필수 검증 시나리오

| 검증 | 기대 결과 |
|---|---|
| 현재 10초 2억원, 직전 10초 1억원 | 가속 200% |
| 현재·직전 모두 0 | 가속 0%, 허위 급증 없음 |
| 현재 > 0, 직전 0 | `신규 유입` |
| 공격매수 6천만, 공격매도 4천만 | 매수우위 60% |
| unknown 비율 40% | 매수우위 `low_confidence` |
| 테마 10종목 중 7종목 상승 | 상승 참여 7/10 |
| 테마 대금 10억 중 1위 6억 | 집중도 60% |
| 같은 체결이 두 원천에서 들어옴 | 한 번만 집계 |
| 상세 UI 재렌더링 | 선택 시간·카드 상태 유지 |
| 15:30 마감 이후 | 정규장 값 고정, 시간외와 혼합 안 됨 |

### 실제 장중 대조

최소 다음 유형을 포함한다.

- 대형주 2종목
- 중소형 급등주 2종목
- VI 발생 종목 1종목
- 상한가 또는 호가 공백 종목 1종목
- KRX/NXT 양쪽에서 거래되는 종목 1종목

## 13. 국내주식에 맞춘 실전 해석

강한 테마의 초기 예시:

```text
공격매수 증가
+ 매수우위 60% 이상
+ 가속 150~200% 이상
+ 상승 참여 60% 이상
+ 집중도 40~70%
```

주의 상태 예시:

```text
공격매수 금액은 크지만
매수우위 50% 미만
+ 가속 하락
+ 상승 참여 감소
→ 거래는 많지만 차익실현·공격매도가 강해지는 상태
```

독주 상태 예시:

```text
집중도 80% 이상
+ 상승 참여 20% 이하
→ 테마 급등이 아니라 한 종목 이벤트일 가능성
```

## 14. 기존 후보5와의 연결 원칙

초기에는 Theme Flow 결과를 후보5 점수에 합산하지 않는다.

권장 단계:

```text
1차: UI 관찰 전용
2차: 후보5 row에 진단 필드만 추가
3차: 리플레이 성과 검증
4차: 대표님 승인 후 점수 가중치 검토
```

향후 후보 입력 후보:

```text
theme_flow_status
theme_buy_dominance
theme_acceleration
theme_rise_ratio
theme_concentration
theme_rank
```

가격·등락률·기존 거래대금 순위 점수를 덮어쓰지 않는다.

## 15. 완료 기준

다음 조건을 모두 만족해야 DONE으로 판정한다.

- 공격매수/매도 방향 판정이 HTS와 장중 검증됨
- unknown과 신뢰도가 API에 명시됨
- 10초·1분·5분·15분 현재/직전 계산이 테스트됨
- KRX/NXT/통합 중복 집계 없음
- VI·상한가·장마감 예외가 처리됨
- 계산은 Python, HTML은 표시만 담당
- 기존 가격 원천·후보5·AHK·런처 동작 회귀 없음
- 리플레이 또는 저장 틱으로 동일 결과 재현 가능
- 대표님 실전 화면 확인 완료

## 16. 구현 담당자에게 전달할 핵심 지시

> 기존 StockBoard의 가격 원천, 후보5 점수, suffix 정책을 변경하지 말고 독립적인 Theme Flow 모듈을 추가한다. 체결 방향은 OpenAPI 원본과 HTS 대조로 먼저 검증하고, 판정 불가능한 체결은 unknown으로 보존한다. 최근 10초·1분·5분·15분과 직전 동일 구간을 비교하여 공격매수, 매수우위, 가속, 대금가속, 상승 참여, 집중도를 Python에서 계산한다. 일반 1분봉만으로 공격매수를 임의 복원하지 않는다. 초기에는 읽기 전용 API와 관찰 UI만 연결하고 후보5 점수 반영은 별도 승인을 받는다.
